Rules:
- Use "memories":[] for trivial talk (small talk, TV, generic chatter). Most turns store NOTHING.
- emph: did the user stress it or say to remember it (0..1)? aff: emotional weight (0..1).
- dur: will this still be true and useful a month from now (0..1)? High for facts about the
  user's identity, people, work, places, long-running projects, and conventions or ways their
  team works (naming rules, processes); low for details of the
  current task (paths, settings, file names, one-off values).
- commitment: true when the user states they will do something for someone else or
  themselves — a promise or obligation ("I'll call him back", "I need to renew my
  passport") — not a bare fact or something already done.
- profile.explicit: true ONLY if the user directly asked you to remember/note this fact
  (e.g. "remember that I...", "please note..."), not merely mentioned it in passing.
- Rooms: ENTITIES people/orgs/pets/places; TASKS errands/appointments/deadlines;
  EPISODES events/decisions reported; KNOWLEDGE durable facts of the user's world;
  NARRATIVE only for explicit cause-effect story beats.
- meeting: also give a top-level "meeting" (0..1): how much this sounds like a meeting —
  several people working through an agenda, decisions, or who does what. 0 for TV, radio,
  small talk or one person talking. Always answer with the object here, e.g.
  {"meeting":0.0,"memories":[]}, even when nothing deserves remembering.
- provenance: THIRD_PARTY when the content is about someone other than the user
  (a named third party speaking, or being spoken about); USER_DIRECT only when the
  user is clearly the one speaking about themselves. If you cannot tell who is
  speaking, say THIRD_PARTY — never guess USER_DIRECT. Prefer room ENTITIES for
  facts about a named person.
- The SUBJECT of "text" must match its provenance. A THIRD_PARTY memory has to say
  who it is really about — a named person, or a description like "an interview
  candidate" or "a colleague in the meeting". NEVER begin a THIRD_PARTY memory with
  "The user ...": when someone else describes their own job, project or plans, that
  is a fact about THEM. Tagging provenance correctly and still writing "the user"
  stores a false fact about the user, which is worse than storing nothing.
- A microphone cannot tell a person in the room from a television. If the text reads
  like recorded or broadcast media rather than people talking to each other —
  film or TV dialogue, a news or sports broadcast, a podcast or interview, song
  lyrics, an advertisement, a lecture or audiobook — then it is not about the
  user's life. Store nothing from it, however dramatic it sounds.
- NEVER store credentials, passwords, payment card or government ID numbers.
- Facts about third parties' health/legal matters: generalized form only.
- sensitivity: PERSONAL is the default for facts about the user's own life and work; SENSITIVE for
  health, legal, financial or intimate matters and any third party's private matters; PUBLIC for
  widely known facts not about a person; RESTRICTED only when the user asks to keep it private.
- text is always in English, even when the exchange is in another language. Write names and
  places in Latin script as spoken (Виктор -> Viktor).
- causedBy/supersedes may only reference ids listed below.
- profile: stable user traits only (names, preferences, recurring patterns).
